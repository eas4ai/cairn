findings:
  - A review finding written in the form AGENTS.md documents, "resolved: <defect, and how>", is refused. For example, "resolved: a defect, fixed by guarding the input" or "resolved: a defect — fixed in abc123" does not carry the report finding "a defect". The kernel accepts only the exact finding text followed by "Resolved:" (optionally after one of . ; : ,), and neither AGENTS.md, LOOP-020 nor the refusal message mentions that convention. Reproduced.
  - A review finding with extra words before "Resolved:", such as "resolved: a defect (reproduced). Resolved: fixed", is refused as "not in it as open or resolved: a defect". The message does not say which form would be accepted. Reproduced.
  - When the review is redone at a later commit and the report still names the earlier, real commit, wake names "repair .cairn/reviews/<slug>.independent.md". AGENTS.md defines repair as "fix the named record as the reason says", which invites the builder to edit the report's commit: line. Doing only that reaches Done with no new independent reviewer, which goes against LOOP-020 and the agreement's "a review redone at a later commit needs a new report there". Before the fix, this case named "review <slug>". Reproduced: after changing only the report's commit: line to the review's commit, wake reported Done.
  - The other repair actions on the report (a wrapped finding, a scalar or misplaced findings list, a wrong commitment) also tell the builder to edit a report that AGENTS.md says to keep verbatim from the independent reviewer. The refusal does not say whether the fix is to reformat the reviewer's text or to ask the reviewer again.
  - The wrapped-finding check runs its regex over all the text before the first heading, prose included, so prose that follows the findings list can trigger it. A report with "findings: []", a blank line, then a prose bullet whose text wraps onto an indented line ("- tried x" / "  and y") is refused with "has a finding that wraps onto a second line", although the report has no findings. The same happens when a wrapped prose bullet follows a real findings list after a blank line. Reproduced.
  - A report finding carried as "resolved: X." (the same text plus a trailing period, with no Resolved: note) is refused when the report says "X", because a trailing period alone is not accepted as a difference. Reproduced. This is minor, but the refusal names the finding without explaining the mismatch.
  - The report is read from HEAD with git show, but the review record is still read from the working tree. A report deleted on disk but not yet committed as deleted still lets Done through. Reproduced. This is a small inconsistency in which state the gate judges.
  - tests/independent.test.mjs no longer covers a report at a real but different commit. The old "another commit" case now uses 0000000, which takes the "not a commit" path, so the stale-report path has no test. There are also no tests for the documented "resolved: <defect, and how>" form, prose after the findings list, or CRLF reports.
