  - A findings list written as a numbered list (1., 2.), as plain indented lines, or as a prose paragraph is read as an empty list, so wake reports Done saying "its independent report are clean" while the report's findings are carried nowhere; reproduced on this repository's own records at a9cd734c, where the tenth report's four findings renumbered 1. to 4. gave Done, and every one of those shapes was refused with an actionable repair by the 13c512de kernel.
  - The same silent drop in the review's own list lets an open finding reach Done: the LOOP-086 falsifier's own shape, an un-bulleted "REM-002: Historical agent checks remain inside role-input JSON rather than readable sections." line under findings: together with "Status: in progress", reports Done at a9cd734c and was "Resolvable: repair .cairn/reviews/first.md" at 13c512de, so the non-list findings value now disappears from the gate instead of producing a verdict naming the file and the supported format.
  - A review or report whose examined: list begins after a blank line is refused with "examined: needs a nonempty list of what the review examined" or "needs a nonempty examined: list", naming a field that is present and correctly written, with nothing naming the blank line as the cause; this is the same shape as the tenth report's finding 3, which the review marks resolved but which was fixed only for findings:.
  - Any extra bullet under findings: in the report becomes a finding the builder is told to carry: a nested detail sub-bullet ("  - one" then "    - reproduced in a scratch clone") and a trailing prose bullet ("- I also read the tests and the walkthrough.") both give "the independent report's finding 2 is not carried", while the identical prose under findings: [] reaches Done, so the refusal still depends on whether the reviewer found anything and the only ways out are carrying prose as a finding or editing a report the agreement says never to edit.
  - An indented line after the findings list, even across a blank line, is glued onto the last entry: a report note "  Reproduced in a scratch clone." makes the refusal read "its review line does not begin with its words: one Reproduced in a scratch clone.", and an indented review note makes it read "a review line cites (independent X 1) but does not end with it; put the citation last on its line" when the citation already ends the line, so neither message names the indented line a developer has to move.
  - A findings entry that sits under a heading is ignored with no word about it: a review with "findings:" in the header and "- open: a real defect I found" under "## Findings" reaches Done, and so does a review that carries finding 1 above the heading and lists a second, unfixed defect below it, so an open finding in the record reaches Done while the loop reads the record only in part and says nothing.
