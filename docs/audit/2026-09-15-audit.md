# Cairn audit, 2026-09-15

Examined commit: fa5ee4f (main, every commitment Done, queue empty)
Requested by: the developer, "a thorough code review looking for gaps,
logic errors, conflicting directives / rules or anything else that
would prevent Cairn from working properly"
Method: four independent read-only review passes (kernel logic,
contract consistency, kernel-versus-spec enforcement, scripts and
operations), each finding then verified by the auditor against the
code or reproduced in a throwaway repository under the session
scratchpad. Nothing in this repository was changed or run against by
the audit; every experiment used copies or fixtures. Unverified
claims are marked as such.

This is a report. It captures nothing to the backlog or
next-iteration and fixes nothing, so that the developer decides
which findings become work; see the closing section.

## Summary

| Severity | Meaning | Count |
|---|---|---|
| BLOCKS | Cairn cannot work, or gives a wrong verdict in a normal flow | 3 |
| WRONG | A wrong result, a crash, or a loop the agent cannot leave, in a plausible state | 15 |
| GAP | A case no code or directive covers, or a gate that does not observe its falsifier | 24 |
| CONFLICT or STALE | Two directives cannot both be followed, or a statement is no longer true | 8 |
| NIT | Message, wording, or cosmetic | 14 |
| Unverified | Reported by a pass, not confirmed | 1 |

The ten findings to act on first, in the auditor's order:

1. A1: the hooks build the kernel path with URL.pathname, so a
   checkout under a path with a space, a percent sign, or a Windows
   drive links a dangling `cairn` and the stop hook silently stops
   blocking.
2. A5: the stop hook judges with its own checkout's kernel while the
   agent checks with the `cairn` on PATH; when they differ, the hook
   blocks forever on "the kernel changed".
3. A12, A13, A14: three states the loop cannot leave. A declaration
   that lists one requirement twice makes every rerun ambiguous; a
   declared input that covers .cairn/evidence/ makes every run dirty
   with its own output; a requirement that keeps its evidence after
   losing its mechanism is a regression "(null)" that declare never
   reaches.
4. B1: the node-test declaration omits files its tests read
   (docs/manual.md, docs/spec, docs/decisions, and every tracked file
   through the package lint test), and docs/ is exempt from scope
   checks, so an edit there can flip the suite without staling any
   evidence.
5. A7: the LOOP-089/090 and LOOP-088 gates are satisfied by the slug
   or item name appearing as a substring anywhere in any escalation
   or decision text.
6. A2, A3, A15: a commitment file whose Requirements: is written as a
   list crashes wake, a subdirectory in a record directory crashes it,
   and a README in .cairn/escalations/ or docs/decisions/ is presented
   as a record to answer or build.
7. C12 and C13: the specification skills tell a consumer's agent to
   run a lint script that only exists in Cairn's checkout, and the
   README tells the user to ask for the skills in prose while the
   skills' frontmatter makes them invocable only by slash command.
8. C2 and C3: DEC-016's falsifier contradicts DEC-017/018 and the
   kernel, and LOOP-026's "exactly these fields" is violated by every
   escalation Cairn writes.
9. B4 and B14: the review gate reads only commit: and findings: from
   the header; a review holding only a commit line, or one whose
   findings sit under a heading, reaches Done.
10. C11: the working agreement names no move for build, resolve,
    repair, commit, implement, declare, or escalate-a-path, and
    states neither record format the kernel validates.

## A. Defects: wrong verdicts, crashes, silent acceptance

A1. BLOCKS on affected paths. bin/hook.mjs:11 sets KERNEL from
`new URL("./cairn.mjs", import.meta.url).pathname`, which keeps
percent-encoding and yields `/C:/...` on Windows. Reproduced: with
bin/ copied under a directory named "dir with space", session-start
printed `linked .../.local/bin/cairn -> .../dir%20with%20space/bin/cairn.mjs`
(a dangling link) and a MODULE_NOT_FOUND stack trace instead of the
verdict; the stop hook from the same copy printed nothing and exited
0, so it never blocks. The same construct is in tests/helpers.mjs:9
and eight other test files, so the suite also fails under such a
path. Fix: fileURLToPath.

A2. WRONG. bin/cairn.mjs:83 calls `.split` on the commitment's
Requirements: value; fields() turns a "- item" list into an array.
Reproduced: `Requirements:\n  - R-001` makes wake exit 3 with
`(f.Requirements ?? "").split is not a function`. Mechanism
declarations use exactly that list form for requirements:, so the
mistake is natural. The stop hook sees no Resolvable and allows the
stop; session-start prints the error as the verdict.

A3. WRONG. mechanisms(), decisions(), escalations(), captureVerdict()
and the queue writer read every entry list() returns, and list()
returns directories too. Reproduced: `.cairn/mechanisms/helpers/run.sh`
makes wake exit 3 with `EISDIR: illegal operation on a directory,
read`. The same holds for docs/decisions/archive/ and any helper
folder beside records.

A4. WRONG. When the project root is below the Git toplevel (a
monorepo package), wake works and check fails. Reproduced with the
project at packages/app: `--root packages/app wake` names run R-001;
`--root packages/app check` exits 3 with `cannot apply Git input
conversion: fatal: could not open '.cairn/mechanisms/m' for reading`
(workingObjects, bin/cairn.mjs:452, feeds paths relative to the
project root to `git hash-object --stdin-paths`). bin/hook.mjs:16
recognizes a roadmap only at the toplevel, so the hooks never fire
there. The requirement that the project root be the Git toplevel is
stated nowhere.

A5. BLOCKS when two checkouts exist. bin/hook.mjs:18 always runs its
own checkout's cairn.mjs, and bin/hook.mjs:29 with
skills/install-cairn/SKILL.md:40-42 deliberately leaves an existing
`~/.local/bin/cairn` link alone. Receipts carry the kernel digest and
a different digest is stale (LOOP-095). Reproduced by the operations
pass with two bin/ copies differing by one comment line: the agent's
kernel says Done, the hook's says `block: run APP-001, evidence is
stale: the kernel changed`, and rerunning check with the agent's
kernel never changes the hook's verdict. This is the state a machine
reaches when the README's checkout install and a second checkout for
the hooks coexist, and it silently breaks LOOP-096 (one referee per
commitment). Fix: the hook runs the kernel the link points at, or
refuses with a message when the two differ.

A6. WRONG. unrealizedDecisions() (bin/cairn.mjs:293) requires
`git rev-parse --verify <sha>^{commit}` to succeed. Reproduced by the
operations pass: the same repository gives `run APP-001` in a full
clone and `build docs/decisions/pick.md` in `git clone --depth 1`.
CI checkouts default to depth 1; nothing in the README or manual says
full history is required.

A7. WRONG. promotedContractVerdict (bin/cairn.mjs:256) treats any
escalation whose text contains the commitment slug as the LOOP-090
escalation; the LOOP-088 check at :795 treats any decision record
containing the item name as the promotion record. Reproduced by the
enforcement pass: with a promoted commitment named `first` and a
revised Agreed requirement, an answered escalation about another
requirement whose Instead: line reads "Try the first option" silences
the gate (control without the word: `escalate first ... (LOOP-089,
LOOP-090)`); a decision saying "We considered some-item" satisfies
LOOP-088 for the item some-item. Common English slugs make this
likely. The LOOP-092 gate at :241 matches on the capture path, which
is narrow enough.

A8. GAP. The footprint and the LOOP-089 comparison both start after
the commit that wrote the Current: line (scopeHistory, began..HEAD).
Reproduced: an activation commit that moves Current: to a promoted
commitment and rewrites an Agreed requirement in the same commit
gives `run R-001`; the same rewrite one commit later gives
`escalate first (LOOP-089, LOOP-090)`. The activation commit is
checked by neither gate.

A9. GAP. fields() is last-wins (bin/cairn.mjs:41). A roadmap with two
Current: lines selects the second silently; LOOP-019 (one commitment
at a time) has no test and no check. Reproduced by the enforcement
pass.

A10. WRONG against the spec. escalate writes `Status: open`
(bin/cairn.mjs:1165) and answer never changes it; the turn is derived
by escalationTurn(). An answered escalation carries both `Status:
open` and `Answer: ok`, which is the derivable status LOOP-028
forbids, written by the kernel itself.

A11. GAP. decide, escalate, answer, backlog, supersede and reversals
skip the repository checks that wake and check perform
(bin/cairn.mjs:1311-1318). Reproduced in an empty directory: decide
exits 3 with a raw `ENOENT ... docs/decisions/stray-decision.md`;
backlog creates `.cairn/backlog/stray-idea.md` there and exits 0.

A12. WRONG, traps the loop. recordEvidence (bin/cairn.mjs:1032) maps
the declaration's requirement list without removing duplicates, and
declarationFieldsError never rejects a repeated identifier. A
declaration listing R-001 twice writes two result lines for R-001
with the same sequence; history() then holds two entries with equal
sequence and historyOrderError reports "history changed or its
execution order is ambiguous" on every wake, and every rerun
reproduces it. Reproduced across two consecutive checks. The
diagnostic never names the duplicate.

A13. WRONG, traps the loop. runMechanism writes the run's .out and
.err under .cairn/evidence/runs/ during execution, then validates the
candidate again with git status, which lists untracked files. A
declared input that covers that directory (`- .` for a
whole-repository lint, or `- .cairn/`) is therefore dirty after every
run: `candidate changed during m; no evidence recorded` with the
action `commit .cairn/evidence/...`. Committing the retained output
does not help, since the next run creates new files. Reproduced for
`- .` across two checks with a commit between.

A14. WRONG, traps the loop. standing() runs with a null mechanism
when no declaration speaks for the requirement; stale is null then,
so the regression branch (latest fails after a pass) and the
three-fails branch fire before wake reaches declare. Reproduced: a
mechanism that spoke for R-001 and R-002, passed, then failed, and
was then narrowed to R-002 gives `implement R-001 / regression:
latest evidence fails after an earlier pass (null)` on every wake;
with three prior attempts it gives `escalate R-001` for a
requirement nothing checks. The only exit is a new declaration,
which wake never names.

A15. WRONG. escalations() and unrealizedDecisions() treat every entry
of their directories as a record, with no name filter (compare
scopeApprovals, which filters). Reproduced by the kernel pass:
`.cairn/escalations/README.md` yields `Escalate: present README`
(exit 2) until someone answers it; `docs/decisions/README.md` yields
`build docs/decisions/README.md` before anything else on every wake.
A subdirectory in either crashes wake (A3).

## B. Gates the kernel does not enforce, and declarations that miss inputs

B1. BLOCKS the freshness guarantee in this repository. The node-test
declaration lists bin/, tests/, skills/, scripts/, AGENTS.md,
CLAUDE.md, README.md and docs/walkthrough.md. Its tests also read
docs/manual.md (tests/skills.test.mjs, the SPEC-026 document test),
docs/spec and docs/decisions (tests/spec-lint.test.mjs lints this
repository's own spec), and every tracked text file
(tests/pkg-lint.test.mjs runs the package lint on the repository
root). An edit to any of those can flip the suite while evidence for
148 requirements stays current, and because breaches() exempts every
path under docs/ (bin/cairn.mjs:149), no scope verdict names it
either. LOOP-006 and LOOP-007's falsifier are live here. Verified by
reading the declaration and the three tests; not exercised against
the repository.

B2. GAP. The pkg-lint declaration omits .cairn/, which the lint reads
for PKG-002 (:37), PKG-003 (:41) and PKG-008 (extensionless receipts
count as text, :17). The operations pass reproduced a non-ASCII byte
in a receipt flagging PKG-008. The spec-lint declaration omits
docs/decisions/, which the LOOP-088 marker check reads
(scripts/spec-lint.mjs:61); deleting a promotion decision fails the
lint with evidence still current. Declaring .cairn/evidence would
stale pkg-lint on every check, so the honest fix is to narrow what
the lint reads or accept the churn.

B3. GAP. breaches() drops every path under docs/ and the three named
root files. The spec says "other than Cairn's own records" (LOOP-035);
docs/manual.md, docs/recon.md, docs/audit/ and any future document are
not records. An in-commitment edit to docs/manual.md reaches Done
without a breach (enforcement pass, E8).

B4. GAP. reviewOf (bin/cairn.mjs:688-700) reads commit: and findings:
only. A review with only those lines, or with an empty examined: list,
reaches Done (enforcement pass, E4, E4b, E12). LOOP-020's "record what
it examined" and SPEC-015's "state what the review attacked" are
observed by no mechanism.

B5. GAP. Decision headers are validated only by the decide command.
decisions() and unrealizedDecisions() read Realized by and Superseded
by; a hand-written or edited record with no Level, Rests on, or Would
be wrong if line reaches Done (DEC-001, DEC-005, DEC-012 unobserved;
tests/wake.test.mjs:36 relies on it). Nothing checks that a
Supersedes: target exists, so deleting a superseded predecessor
erases the reversal: `reversals: 0 of 1 decisions` (DEC-010).

B6. GAP. Escalations on disk are never format-checked (LOOP-012); a
hand-written file with one field and thirty filler lines is presented
as is. Consistent with LOOP-013's precedence, but "return to the agent
for rewriting" never happens for a file.

B7. GAP. Evidence is recorded for every requirement a mechanism speaks
for, Draft or Observed included, by any check that runs it.
Reproduced: `check R-002` with R-002 marked Draft records
`R-002: pass`. Wake never uses it, since a commitment cannot name the
requirement, but the receipt claims a result against non-contract
text.

B8. GAP. The kernel reconciles an existing .cairn/in-progress record
but never demands one: dirty declared inputs with no record give
`run R-001 ... a declared input changed`, never "no record names the
action" (LOOP-022's falsifier; enforcement pass, E9).

B9. GAP. withAnswer attaches a developer's answer only to actions
that name a requirement or a scope incident. The LOOP-092 capture
escalation (`escalate .cairn/next-iteration/<item>.md`) and the
LOOP-090 escalation (`escalate <slug>`) are silenced by the file's
existence, and an `instead` answer to either is shown by no wake.

B10. GAP. The LOOP-090 route runs two gates in sequence: captureVerdict
fires on the moved item unless an escalation names its path, and
promotedContractVerdict fires unless an escalation names the slug.
One escalation at a time (LOOP-011) means the single escalation must
name both, and neither the working agreement nor the wake reason says
so.

B11. GAP. Read failures inside the kernel (`cannot read the
commitment's Git history`, `cannot read the commitment's captures`,
`cannot list declared inputs`) throw to usage() and exit 3 rather than
naming a Resolvable repair (LOOP-005). Code reading only.

B12. GAP. bin/hook.mjs ignores stop_hook_active (verified: a stdin
with `"stop_hook_active": true` still blocks). Claude Code's own cap
of eight consecutive blocks bounds it, as package.md:186 says; the
Codex cap the manual claims (docs/manual.md:643-644) is unverified.
An agent that cannot act on the action (A5; a lock held by another
live process; a repair on a file it may not edit) spends eight turns
per stop.

B13. GAP. session-start throws ENOTDIR uncaught when $HOME/.local/bin
is a regular file (exit 1, no verdict), and keeps a pre-existing
dangling link silently; skills/install-cairn/SKILL.md:62 then
diagnoses the resulting "command not found" as a PATH problem.
Operations pass, verified.

B14. GAP. recordFields ends the review header at the first heading or
prose line, and a missing findings: key reads as an empty list. A
review whose findings sit under a `## Findings` heading, or that
omits the key, reports Done (kernel pass, reproduced). LOOP-086 makes
an empty list valid; a missing list is silently the same. Every
review in this repository carries findings: in its header, so no
recorded verdict was affected.

B15. GAP, platform. fileIdentity takes the mode from lstat and
committedInputsDigest hashes that mode with the Git object id, while
inputsDigestAt hashes the tree mode. With core.filemode=false on a
mount where every file reports the executable bit (NTFS, FAT, drvfs)
the two never agree, every check ends in `commit candidate for m;
inspect Git flags, file modes`, and committing cannot fix it.
tests/candidate.test.mjs:667-681 asserts the refusal for a chosen
chmod; the platform case is inferred from that path and was not run.

B16. NIT. An invalid cwd: in a declaration is not a declaration
error; the spawn fails, the receipt records `exit: -2` with the spawn
error, and every requirement the mechanism speaks for is recorded
fail under legacy reporting, which counts as an attempt. LOOP-062
says -1 when execution could not start. Kernel pass, reproduced.

B17. NIT. `check --stale` prints "nothing stale: every requirement
with a mechanism has current evidence" while a receipt needs repair,
because standings with a repair are skipped before the summary
(bin/cairn.mjs:978); the closing wake does say repair. A review
without a commit: line is reported as "a requirement or falsifier
changed since the review" and later as "the review examined ?", never
as a missing line. A seven-character Realized by hash that has become
ambiguous makes the decision unbuilt with a message saying the commit
is missing. A stop-hook stdin with a non-string cwd (`{"cwd": 5}`)
throws uncaught, exit 1 with a stack trace.

## E. The two lints

E1. WRONG. spec-lint's SPEC-019 scan runs over raw lines, so
backticks do not protect a path-shaped token: a regex literal such as

matching, so `file:///tmp/secret` and Windows `C:\Users\...` paths
pass. All nine rules it implements did catch one deliberate violation
each.

E2. WRONG. pkg-lint's PKG-003 check (scripts/pkg-lint.mjs:40) scans
the `// cairn <cmd>` header comments of bin/*.mjs; the falsifier names
"a command in the kernel's usage text". A command present in help()
and dispatch but not in the header passes (operations pass fixture).

E3. GAP. pkg-lint's PKG-006 is a per-line verb-plus-product regex

E4. NIT. spec-lint's PKG-010 actor check strips backticked and quoted

## What this report does not do

It changes no code and captures nothing. Each finding above is a
candidate for the backlog (inside the specification) or for
next-iteration (it would change an Agreed requirement, its falsifier,
or the working agreement: C2, C3, C8, C11, C15, C18, and the LOOP-035
docs/ exemption in B3 are of that kind). Sorting and capturing them is
a decision the developer makes, because unpromoted backlog items turn
the next Done into promote and start the loop again.
