# Iteration 001 -- Engine layer L1: obligation store and lifecycle

Status: Scope contract
Agreed: 2026-09-02

The engine spec is docs/superpowers/specs/2026-09-02-same-page-conformance-engine.md.
"Shipped" for a requirement means: implemented in
skills/new-project/scripts/engine/, with a test in tests/ that
produces the requirement's falsifier state and shows the engine
refusing it, and the evidence map row raised to Covered with that
test cited; for a workflow requirement, the named SKILL.md text
carries the step and the row is Asserted by inspection.

## In

Engine surface, TypeScript under skills/new-project/scripts/engine/,
entry `same-page.ts`, commands `elaborate` and `verify` (L1 scope):

- ENG-002 -> `elaborate` writes the confirmed falsifier into each
  obligation, verbatim from the Falsifier line.
- ENG-010, ENG-011 -> `elaborate` takes only requirements under an
  Agreed file or section, and no engine command writes to a spec.
- ENG-012 through ENG-016, ENG-018 through ENG-020 -> one obligation
  file per Agreed `MUST` or `MUST NOT` requirement, keyed on the
  identifier, holding the identifier, the requirement locator, the
  requirement digest, the falsifier, the falsifier digest, the
  profile, the validators list, and the copied requirement sentence;
  `verify` reports an obligation invalid when a digest no longer
  matches the spec, and evaluates the spec, never the copy.
- ENG-021, ENG-023, ENG-024 -> the falsifier is stored as text and
  never parsed as commands; `elaborate` refuses a `MAY` requirement
  and refuses an Agreed `MUST` that has no Falsifier line.
- ENG-070, ENG-072, ENG-073, ENG-075, ENG-076, ENG-077 -> the policy
  file is parsed and validated: a profile is a composition, freshness
  is required and cannot be waived, a project default exists, a domain
  override is accepted, and an obligation naming no profile takes the
  nearest default. The first `elaborate` writes `policy.yaml` when it
  is absent, with the default profile named below.
- ENG-078, ENG-079 -> the stage-close step applies the default and
  asks only when a requirement needs a different profile
  (SKILL.md text).
- ENG-186 through ENG-190, ENG-192, ENG-193 -> the `.same-page/`
  layout: `obligations/<ID>.yaml`, `validators/`, `policy.yaml` as
  committed text; `evidence/` and `cache/` created with a `.gitignore`
  that excludes them; no database, no lock file. The engine ships its
  own reader and writer for the YAML subset it emits (block mappings,
  block sequences, plain and quoted scalars, literal block scalars,
  comments); every file it writes is valid YAML 1.2.
- ENG-197 -> neither `elaborate` nor `verify` writes conformance.md.
- ENG-205 through ENG-208, ENG-211 -> the falsifier is recorded at
  confirmation (SKILL.md, already true); stage close runs `elaborate`
  (SKILL.md); machine detail stays in `.same-page/`; digests are
  computed, never asked for.
- ENG-216, ENG-217 -> no documented step hand-authors an obligation;
  a profile or validators value set by hand in an obligation file
  survives re-elaboration, and the derived fields are refreshed.
- ENG-225, ENG-230, ENG-231 -> /new-project stage close, and
  /next-iteration promotion, name the elaboration step; /existing-project
  Stage 4 names it after the contract.
- ENG-232, ENG-233, ENG-235 -> the drift gate is unchanged by this
  iteration.
- ENG-240, ENG-241 -> this contract: L1 presupposes nothing.
- PKG-001, PKG-002, PKG-006 -> the engine declares no dependency,
  runs under node and bun (a test spawns it with both), and lives
  under skills/new-project/scripts/.

The default profile, written into `policy.yaml` by the first
`elaborate`: the project default is named `default` and requires any
one evidence method other than `inspected`, so its sufficiency matches
the evidence map's Covered; stricter profiles are added per domain by
the developer. `policy.yaml` also lists the spec directories the
engine reads (`specs:`), defaulting to the project's docs/specs/
directory; this repository lists both of its spec directories.
