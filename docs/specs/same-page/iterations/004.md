# Iteration 004 -- Engine layer L3: conservative freshness

Status: Scope contract
Agreed: 2026-09-03

The engine spec is docs/superpowers/specs/2026-09-02-same-page-conformance-engine.md.
Iterations 001 through 003 are closed; this contract presupposes L1
and L2 (ENG-241). "Shipped" keeps its meaning: implemented under
skills/new-project/scripts/engine/, with a test in tests/ that
produces the requirement's falsifier state and shows the engine
refusing it, and the evidence map row raised to Covered with that test
cited; a workflow requirement is Asserted by inspection of the named
text.

## In

- Evidence identity, ENG-140 through ENG-145 -> every record stores
  its identity inputs as one block: the snapshot, the requirement
  identifier, the requirement and falsifier digests, the obligation
  digest (over the contract projection: identifier, locator, keyword,
  digests, falsifier, validator names; never profile, required, or
  policy), the validator definition digest, the adapter identity and
  version, the dependency fingerprint (the boundary's content, which
  at the repository scope is the snapshot), the environment
  fingerprint, and declared external contracts; any input that differs
  now ends `current`; policy is never an input, so a policy edit
  re-evaluates and never stales.
- Freshness, ENG-121 through ENG-126, ENG-128, ENG-129 -> the third
  state: `stale` when an identity input is known to differ, `unknown`
  only when one cannot be computed; the chain runs in order with steps
  one and two answering "no mechanism" until L6, step three the
  repository, step four `unknown`; every record names its scope and
  `narrowing: none`; no hand-declared list or run trace ever decides
  freshness.
- Verification boundary, ENG-130, ENG-132, ENG-133 -> the boundary is
  a recorded structure (scope, root, the validator definition, the
  declared environment inputs, the assumptions), and every `verify`
  entry states the residual risk outside it.
- Environment fingerprint, ENG-150 through ENG-152 -> a validator
  definition declares `environment:` as a list of inputs, each a
  `command` (argv whose output is the fingerprint) or a `file` (path
  whose digest is the fingerprint), or an explicit empty list; `run`
  records exactly those, `verify` recomputes them, a difference is
  `stale`, a failure to compute is `unknown`, and drift outside the
  declaration is residual risk on the record and in the entry. A
  definition with no `environment:` key is a finding and produces no
  record.
- Verdicts under the third state, ENG-084, ENG-085 as agreed ->
  `BLOCKED` only for `unknown` (and validator error, digest mismatch);
  `stale` evidence is shown and yields `INSUFFICIENT` with the re-run
  named; `FAILING` needs a current failing result; a standing disproof
  on stale evidence is shown as standing.
- The bun-test validator of this repository declares its environment:
  the bun version and node version by command, package.json by file.

## Out

  Decisions and revisions carry the decisions above; version 0.8.0.
