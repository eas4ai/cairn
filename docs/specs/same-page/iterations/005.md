## In

- Verification authority, ENG-155 through ENG-160 -> the policy
  carries `authority:` (`ci`, `local`, or `named-environment` with
  `authority_name`); the default is `ci` when the repository holds
  owner-controlled CI configuration at a recognized path
  (.github/workflows/, .gitlab-ci.yml, .circleci/config.yml,
  Jenkinsfile, .buildkite/, azure-pipelines.yml, .travis.yml,
  bitbucket-pipelines.yml, .drone.yml, .woodpecker.yml), else `local`,
  and the first `elaborate` writes it explicitly; a value outside the
  three is a finding. A record carries the authority of its execution
  context: trust-record and developer-invocation are `local`; a run
  inside CI (the `CI` environment variable set and the configuration
  present) is `ci` and writes under .same-page/artifacts/ci/; a named
  environment needs a grant outside the repository (`same-page trust
  --environment <name>`) and `run --environment <name>`, and writes
  under .same-page/artifacts/environments/<name>/. A record whose
  stored authority contradicts its location is refused (ENG-194).
  Only records of the configured authority at the exact snapshot can
  yield `SUFFICIENT`; non-authoritative records are shown with their
  authority, and when they alone would satisfy the profile the entry
  is `INSUFFICIENT` with "current locally; not yet established by
  authoritative <authority>". A current failing record from any
  authority is `FAILING`: a demonstrated counterexample is never hidden
  behind authority.
- Machine view and map comparison, ENG-195, ENG-196, ENG-198, ENG-199
  -> `verify` computes the machine view of coverage per obligation:
  Covered when a pass-or-fail record beyond inspection addresses the
  falsifier, with its methods; Asserted when only inspection records
  exist; Uncovered when none; and reports every row where the map
  disagrees. No records agrees with Asserted and with Uncovered, since
  both claim no mechanism. ENG-197 stays as built.
- Synchronization, ENG-200 (and ENG-201 in the skills) -> `same-page
  sync-map` rewrites the Coverage and Method of disagreeing rows, fills
  Evidence only when it is empty (the validator definition path, or
  `manual: <actor>`), writes `-` and empty on Uncovered, adds a row for
  an obligation that has none, and never writes freshness or a
  verdict.
- Workflow requirements ENG-225 through ENG-232 and ENG-235 -> Asserted
  by inspection of the named skill or script text; the existing-project
  Path B text consults `same-page verify` before re-deriving a section
  (ENG-226).
- This repository's policy states `authority: local` (00-overview.md,
  developer ruling 2026-09-02).
