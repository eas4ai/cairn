## In

- The adapter registry, ENG-055 and ENG-056 -> every adapter is
  registered with explicit capabilities: the built-in `command`,
  `manual`, and `tsc-closure`, plus registrations the developer keeps
  outside the repository in `$SAME_PAGE_HOME/adapters.yaml` (name,
  version, capabilities, command). An adapter with no registration
  produces no record, and a claim whose capability the registration
  lacks is refused.
- Adapter trust, ENG-061 through ENG-065 -> `same-page trust --adapter
  <name>` grants one adapter for one repository, in the trust store
  outside it, bound to the adapter's name and version. Repository
  content requests an adapter and never grants one; without the grant
  the engine keeps the conservative floor and names the grant to write.
- Sound narrowing, ENG-124 step one, ENG-127 through ENG-129 -> a
  validator definition declares `closure:` naming a trusted adapter
  that holds `can_establish_complete_dependencies`, with the project
  the closure covers. The adapter computes the input set; the record's
  dependency scope becomes `package`, its provenance
  `adapter_derived`, its narrowing a reviewable act naming the adapter,
  its version, the project, and the input count, and its dependency
  fingerprint is over that input set instead of the snapshot. A change
  inside the closure makes the record stale; a change elsewhere in the
  repository leaves it current. Chain step one succeeds, and the
  boundary line states the narrowed scope.
- Supplemental traces, ENG-041 and ENG-042 -> a validator definition
  declares `trace:` as a command that names further inputs. Traced
  inputs are fingerprinted and widen the record's identity; they never
  narrow a scope and never establish completeness. The record's
  provenance becomes `traced_supplemental`, and a trace that names a
  path outside the repository makes a change to that path stale the
  record.
- Formal results, ENG-166 and ENG-167 -> a record whose method is
  `formal` carries the correspondence assumption between the
  requirement sentence and the formal model, and every `same-page
  verify` entry backed by one states it.
- Dogfood: this repository declares an `engine-typecheck` validator
  whose closure the `tsc-closure` adapter establishes over
  skills/new-project/scripts/engine.

## Out

- Backend bindings and challenge establishment by adapters: no
  registered adapter holds `can_establish_binding` or
  `can_establish_challenge`, and the engine keeps refusing both
  (ENG-032, ENG-035).
- Further ecosystem adapters for databases, browsers, services, and
  formal-verifier backends: the registry is the extension point, and
  each such adapter is its own change.
- Any change to the drift gate, the language check, or the templates.
