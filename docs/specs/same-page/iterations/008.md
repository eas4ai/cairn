# Iteration 008 -- Remediation: sensitivity claims and their reach

Status: Scope contract
Agreed: 2026-09-03

The engine spec is docs/superpowers/specs/2026-09-02-same-page-conformance-engine.md.
Iterations 001 through 007 are closed; all six construction layers are
built. This contract corrects three defects the release audit found in
layer L5 and states two decisions the developer deferred to the model.
No requirement text changes: the engine moves to what the agreed
sentences already say.

## In

- Weak sensitivity clears, ENG-173 and ENG-174 -> a recorded miss
  carries the challenge that produced it, and a subsequent run of that
  same challenge which the validator notices clears the miss, with the
  clearing timestamp recorded beside it. A cleared miss stays as history and stops
  withdrawing claims. `same-page verify` reports an uncleared miss as a finding and
  shows a cleared one as prior weak sensitivity on the entry, the way a
  prior disproof already appears. The defect this corrects: a miss withdrew every challenged claim
  recorded after it, permanently and with no way back, while
  docs/WORKFLOW.md said the claim returns when a challenge succeeds
  again.
- The reach of a miss, ENG-174 -> sensitivity is a property of the
  mechanism, so an uncleared miss withdraws that validator's challenged
  claims for every requirement it serves, not only for the requirement
  whose falsifier the challenge realized. Misses are stored per
  validator under `.same-page/evidence/_mechanisms/<validator>.yaml`,
  derived state like every other evidence file. The defect this
  corrects: the engine was narrower than the requirement it implements.
- What a challenge speaks for, ENG-036 and ENG-037 -> every challenge
  declaration names its subjects. A declaration with `from_falsifier:
  true` names one `requirement`, whose confirmed falsifier it realizes.
  A declaration with `from_falsifier: false` names a `requirements:`
  list, and each entry lists that validator on its obligation. A
  challenge claims nothing by default. The defect this corrects: one
  demonstration granted challenged sensitivity to every obligation the
  validator was bound to, which on this repository would be 140
  requirements.
- Documentation of what `same-page verify` runs -> CLAUDE.md,
  docs/WORKFLOW.md, docs/MANUAL.md, and the new-project skill state
  that verify executes the declared environment commands and recomputes
  adapter closures under the same execution trust as `run`, and that it
  is therefore slower than a report.
- Documentation of evidence growth -> docs/MANUAL.md and
  docs/specs/same-page/conventions.md state that evidence accumulates
  one record per obligation per run, that the engine never deletes it,
  and that the directory is derived, uncommitted state under the
  developer's control.

## Out

- Any change to a requirement's text or its confirmed falsifier: this
  contract moves the engine to the agreed sentences.
- Deleting or pruning evidence from inside the engine, which ENG-087
  and ENG-117 forbid.
- Extracting the shared trust, authority, environment, and dependency
  resolution out of same-page.ts. That refactor is real and stands
  next, under its own change, so a behavior fix and a structural move
  never land in one commit.

## Definition of done

- A test produces each corrected behavior's falsifier state: a miss
  that a subsequent success clears; a miss that withdraws a claim on a
  requirement other than the one it named; a challenge declaration that
  names no subject.
- `bun test` passes; the language check reports zero findings for both
  spec directories; `bunx tsc --noEmit -p
  skills/new-project/scripts/engine` clean; the ASCII gate returns
  nothing; `claude plugin validate . --strict` passes.
- Dogfood on this repository at a clean commit: the CONF-016 challenge
  still records challenged sensitivity, and `same-page verify` reports
  no finding and no map disagreement.
- Docs current, the engine spec's Decisions and revisions carries the
  decisions above, and version 1.1.0.
