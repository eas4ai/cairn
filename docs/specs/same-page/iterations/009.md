# Iteration 009 -- The engine's command line, decomposed

Status: Scope contract
Agreed: 2026-09-03

The engine spec is docs/superpowers/specs/2026-09-02-same-page-conformance-engine.md.
Iterations 001 through 008 are closed. This contract changes structure
and nothing else: every command keeps its behavior, its output, and its
exit code, byte for byte.

## In

- same-page.ts is reduced to the command line itself: argument parsing,
  the project root, and dispatch. Everything else moves out.
- The shared plumbing moves to project.ts: the project root, the spec
  directories, the .same-page layout, the policy file, the obligation
  store, and the finding printer.
- Permission and dependency resolution moves to execution.ts: the
  execution trust context and authority an invocation runs under, the
  environment fingerprint, the adapter closure, the supplemental trace,
  and the `trust` command. `run` and `challenge` each carried a copy of
  this resolution and of the evidence-record fields it produces; both
  now call one resolver and one record builder.
- The commands move to files named for what they do: elaboration.ts
  (`elaborate`, `policy confirm`), verification.ts (`verify`,
  `sync-map`), runs.ts (`run`, `challenge`), attestation.ts (`attest`,
  `acknowledge`). The lines `verify` prints move to render.ts.
- CLAUDE.md's architecture section lists the modules as they stand
  after the move.

## Out

- Any change to what a command does, prints, or returns. A behavior
  change under this contract is a defect, not an improvement.
- Any change to a requirement, a falsifier, the evidence map, the
  policy, or the on-disk format of any file the engine reads or writes.
- Any new command, flag, or module boundary beyond the ones listed.

## Definition of done

- `same-page verify`, `same-page elaborate`, `same-page sync-map`, and
  the usage message produce output identical to the output captured
  before the move, compared byte for byte on this repository.
- `bun test` passes with the same 125 tests, unchanged: the suites
  exercise the engine through its command line, so an unchanged suite
  over changed structure is the evidence that behavior held.
- The language check reports zero findings for both spec directories;
  `bunx tsc --noEmit -p skills/new-project/scripts/engine` clean; the
  ASCII gate returns nothing; `claude plugin validate . --strict`
  passes.
- No file under skills/new-project/scripts/engine/ exceeds 500 lines.
- Docs current, the engine spec's Decisions and revisions carries the
  decision above, and version 1.1.1.
