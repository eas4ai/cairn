# Iteration 010 -- A trace that failed is not a trace that found nothing

Status: Scope contract
Agreed: 2026-09-03

The engine spec is docs/superpowers/specs/2026-09-02-same-page-conformance-engine.md.
Iterations 001 through 009 are closed. This contract corrects one
defect and one reporting gap that the decomposition in 009 made visible.
No requirement text changes.

## In

- A failed trace is recorded, ENG-140 and ENG-142 -> when a validator
  declares `trace:` and the command that computes it fails, the record
  carries that failure on its identity, as a declared environment input
  that cannot be computed already does. `same-page verify` then reads
  the record's freshness as `unknown` and states the reason. The defect
  this corrects reaches further than the audit first said: both `run`
  and `challenge` wrote a record whose traced inputs were never
  captured, and `verify` treated that record as current, because it
  compares a traced fingerprint only when the record carries one. A
  traced input could therefore change while the record stayed current,
  which is the falsifier of ENG-140.
- The freshness a record states, ENG-126 -> `challenge` marks a record
  `unknown` when the trace it declared could not be computed, as `run`
  does. The two commands share one resolution after iteration 009, so
  the condition is stated once.
- What a challenge reports while it runs, ENG-126 -> `same-page
  challenge` reports a declared environment input it cannot compute, at
  the moment it writes the record, as `same-page run` does. Before this
  the command exited silently and the developer met the consequence at
  the next `verify`.

## Out

- Any change to a requirement, a falsifier, the evidence map, or the
  on-disk format of anything other than the identity block, which gains
  one field.
- Binding a validator to any of the 23 obligations that have none, and
  confirming the design, language, and conformance specs from Draft to
  Agreed as files. Both stand open, and both are the developer's call
  rather than a defect.

## Definition of done

- A test produces each corrected behavior's falsifier state: a record
  written while its declared trace failed, which `verify` refuses to
  call current; and a challenge that reports an environment input it
  cannot compute.
- `bun test` passes; the language check reports zero findings for both
  spec directories; `bunx tsc --noEmit -p
  skills/new-project/scripts/engine` clean; the ASCII gate returns
  nothing; `claude plugin validate . --strict` passes.
- Dogfood on this repository at a clean commit: `same-page verify`
  reports no finding and no map disagreement, and the CONF-016
  challenge still records challenged sensitivity.
- Docs current, the engine spec's Decisions and revisions carries the
  decision above, and version 1.1.2.
