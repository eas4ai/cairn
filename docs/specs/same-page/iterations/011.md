# Iteration 011 -- Every agreed requirement gets a mechanism

Status: Scope contract
Agreed: 2026-09-03

The engine spec is docs/superpowers/specs/2026-09-02-same-page-conformance-engine.md.
Iterations 001 through 010 are closed. Twenty-three Agreed requirements
carry no evidence mechanism. The developer ruled that a mechanism's
absence is a defect, not a standing decision. Twelve of them can be
checked against this repository as it stands, and this contract builds
those. The remaining eleven state what happens inside a live workflow
session, which no validator in this repository can observe; they are
listed in Out with what each one needs.

## In

- The package's own rules, PKG-003, PKG-004, PKG-006 -> a validator
  runs the ASCII gate the conventions name, and tests assert that no
  shipped template carries a bracketed placeholder and that the drift
  gate, the language check, and the engine all live under
  skills/new-project/scripts/.
- Falsifier text is data, ENG-023 -> a test gives a requirement a
  falsifier whose lines read as commands and shows that elaboration and
  verification never execute or parse them.
- Records the engine refuses, ENG-032, ENG-072 -> a test writes a
  record claiming a backend binding no registered adapter can establish
  and shows it refused; another shows that no profile yields
  `SUFFICIENT` over evidence whose freshness is `stale` or `unknown`.
- The machine view of manual evidence, ENG-184 -> a test shows that a
  manual record which did not address the falsifier projects to
  Asserted, and one that did projects to Covered.
- The vocabulary the engine does not own, ENG-229 -> a test shows that
  no engine surface prints `Holds`, `Drifted`, `Still Observed`, or
  `Missing`.
- The gate stays an audit, ENG-232 -> a test shows the drift gate's
  output carries no validator result and no verdict it computed.
- The layers, ENG-240, ENG-241 -> a test scans the specs, the
  contracts, and the docs for a layer described as optional or out of
  scope, and checks that every layer an iteration contract includes has
  its dependency layers built or included.
- What the developer is never asked to write, ENG-216 -> a test scans
  the skills and the docs for a step that tells the developer to write
  an obligation file, a digest, a dependency provenance, or an evidence
  record by hand.
- Each requirement above gets its obligation bound to the validator
  that carries it, and its evidence-map row cites the test.

## Out

- The eleven requirements whose falsifier occurs inside a live workflow
  session, which no mechanism in this repository observes: ENG-078,
  ENG-079, ENG-104, ENG-116, ENG-208, ENG-225, ENG-226, ENG-228,
  ENG-230, ENG-231, and ENG-025, whose falsifier has a second half the
  language check does not yet detect. The engine's answer for these is
  manual evidence by a named actor with an expiry, which needs the
  developer to say who attests and how long the attestation stands, or
  a session-transcript mechanism, which is a feature and not a fix.
  Both stand open and neither is silently dropped.
- Any change to a requirement, a falsifier, or the engine's behavior.

## Definition of done

- Every requirement named In has an obligation bound to a validator, a
  test that produces its falsifier state, and a map row citing that
  test.
- `bun test` passes; the language check reports zero findings for both
  spec directories; `bunx tsc --noEmit -p
  skills/new-project/scripts/engine` clean; the ASCII gate returns
  nothing; `claude plugin validate . --strict` passes.
- Dogfood on this repository at a clean commit: `same-page verify`
  reports 167 obligations SUFFICIENT, eleven INSUFFICIENT, no finding,
  and no map disagreement.
- Docs current, the engine spec's Decisions and revisions carries the
  decision above, and version 1.2.0.
